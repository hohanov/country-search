# Описание реализации

## Отмена запросов и debounce

`SearchController.setQuery` при каждом изменении ввода сразу отменяет debounce и активный запрос, затем планирует новый поиск через 300 мс. Очистка поля отменяет запрос и возвращает экран в исходное состояние. Результат применяется только для текущего запроса.

`CountrySearchService` объединяет одинаковые запросы. У каждого вызова свой сигнал отмены; общий запрос прерывается, когда отменились все ожидающие. Таймаут создаётся через `AbortSignal.timeout`. `AbortError` игнорируется, таймаут и сетевые/HTTP-ошибки показываются с кнопкой повтора, а HTTP 404 считается пустым результатом.

Задержка 300 мс сокращает число запросов при наборе. Без debounce запрос отправлялся бы на каждую клавишу.

## Сложность

Для `n` стран и `m` суммарных элементов языков, границ и валют `mapCountryResponse` работает за **O(n + m)** и создаёт результат за **O(n + m)**. Поиск по кэшу и таблице запросов в `CountrySearchService` занимает **O(1)** в среднем на запрос; память кэша пропорциональна числу сохранённых результатов. Добавление в историю до 10 запросов занимает **O(h)** для текущей длины истории `h`.

## Чистый код

-   Разделение ответственности: API — `search-countries.ts`, преобразование данных — `map-country-response.ts`, состояния и отмена — `search-controller.ts`, DOM — `main.ts`.
-   Тип `SearchState` явно задаёт состояния экрана; DOM строится без вставки динамического HTML.
-   Логику проверяют тесты с моками сети и хранилища, без реальных запросов.
